Saved card surfacing on cart

enrich type · capability owner · Jules (UX) last update · 14m ago runs · 7 total

Intent

Returning users who already have a tokenized card on file should see it surfaced as the default on the cart page, so the path to confirmation collapses to a single click — without changing PCI scope or breaking guest flows.

Outcomes

01 Returning users with saved cards complete checkout in fewer than three clicks. ≤ 3 clicks · measured
02 Cart-to-confirmation conversion lifts measurably for the saved-card cohort. +8% · target
03 No regression to guest-flow conversion or to PCI audit boundary. guard · invariant

Slices · 3 of 4 ready

Card list component

Compact list of tokenized cards with last-four, brand glyph, expiry. Default highlighted. Keyboard navigable. Uses existing design tokens.

build · merged Matt · #421
Default card selection logic

Pick most-recently-used card unless user-flagged preference exists. Falls back gracefully when token expired or revoked.

build · in PR Matt · #427
A/B test wiring

50/50 cohort split keyed on user_id hash. Surface treatment via feature flag. Telemetry events emit to existing pipeline.

test · drafted Tom · 12 cases
Telemetry contract

Define and document the event schema for saved-card surface, click, dismiss, fallback. MSSQL ingestion table updates.

UX gate · waiting Jules · 2h

Open questions

? When a saved card is expired but the user hasn't been notified — surface the card with a warning, or hide it? unresolved
? Default selection ambiguity for users with cards across multiple brands — most recent vs. user preference vs. issuer rules. UX gating

Content · v1 edit

A feature is "ready" when it has all of the
following, or the missing ones are explicitly
flagged:

  · a stated problem (not a solution)
  · ≥ 1 measurable desired outcome with metric_hint
  · named constraints (regulatory, technical, time)
  · identified stakeholders
  · explicit open questions
  · acknowledged dissent (if any)

Your extraction MUST populate all six. If a field
cannot be derived from the source, set it to null
and add it to open_questions with reasoning. Do
not infer numbers; suggest metric_hint without
inventing values.
